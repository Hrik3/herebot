## Original mechanism and root cause

`build_world_model_transitions()` converted `factor_vector.values()` to a
positional array and aligned it to the current representation.  `StateManager`
then cosine-compared that array to an old stored positional state with raw
`np.dot`.  A later factor addition made the query 13-dimensional and the old
state 11-dimensional, producing E10.  More fundamentally, neither positional
array recorded its factor-space identity or schema version, so equal length
would also have been insufficient proof of semantic equivalence.

## Chosen design

`components/factor_space.py` introduces one reusable `FactorSpace` abstraction
without merging the two registries.  `MetaCuriosityLearner` owns `meta`; the
control system owns `control`.  A snapshot contains `space_id`, monotonic
`version`, ordered `factor_names`, and factor metadata/history.  Factor names
are semantic identity; positions are local serialization indices only.

State records now persist the original vector unchanged with
`factor_space_id`, `factor_space_version`, `factor_names`, and factor statuses.
Episodes retain their name-keyed dictionary and now persist the same schema
metadata.  Meta-learner arrays and control-space schemas persist their
FactorSpace history beside existing learned parameters.

## Comparison and migration semantics

Comparison is `shared_observed_factor_names_cosine`: two observations are
aligned by name and cosine is calculated only for factors observed numerically
in both.  It returns an audit record with both versions, shared and excluded
names, policy, timestamp, and event id.  `OBSERVED`, `ABSENT`, and
`UNAVAILABLE` are distinct; no NaN or runtime 0.5 fallback is used in cosine.

Projection is a separate explicit operation.  `StateManager.project_state()`
maps same-name factors and records source/target schemas, shared/new/retired
names, policy, timestamp, and event id.  New factors default to explicit
`ABSENT` with no numerical value unless a caller declares `default:<number>`.
Projection never mutates the historical state.
Actual projections and legacy compatibility inferences are additionally written
append-only to `curiosity_state/factor_space_migrations.jsonl`.

Legacy state files lacking metadata load as explicitly marked v0 compatibility
records.  Because the old control implementation only appended dynamic factors,
a query with a supplied descendant control schema may use the documented prefix
inference; that inference is recorded in the audit.  Otherwise legacy positions
remain unaddressed and are not silently reinterpreted.  Existing files are not
rewritten.

## Hard invariants

The meta learner now rejects any mismatch among `mu`, `lambda_`, `alpha`,
`beta`, and `factor_names`, including in `update`, `predict_curiosity`, and
`get_weights`.  Control vectors must match the exact current control-space
version and ordered names.  Reordering a persisted schema under a fixed version
raises `FactorSpaceInvariantError`; neither side pads, truncates, or silently
repairs itself.

## Performance and known limitation

Snapshots retain name→index maps through their immutable ordered names and
state comparison retains a bounded in-memory audit list.  Comparison touches
only the shared names; it does not reconstruct or rewrite state JSON files.

Dynamic factor compute closures remain RAM-only and are not serialized.  After
restart their existing runtime fallback behavior remains unchanged.  This is a
known separate issue and is deliberately not addressed here.
